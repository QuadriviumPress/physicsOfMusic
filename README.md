# Physics of Music

An open textbook on the physics of musical sound — vibration and wave motion,
standing waves and resonance, spectrum and timbre, the ear and the perception of
loudness and pitch, tuning systems, the instrument families, room acoustics, and
recorded sound — written for a one-semester course for students of any major.

No calculus is required. The main argument runs on algebra, trigonometry, and
ratios; derivations that genuinely need calculus are placed in dropdowns and are
never depended on afterwards.

Built with [MyST Markdown](https://mystmd.org). The website, a print PDF in two
editions, and a Word edition all come from the same source.

## Getting started

Node 22 and npm 10; the versions are declared in `.nvmrc`, `.node-version`, and
`package.json`.

```bash
nvm use
npm ci
npm start          # live preview at http://localhost:3000
```

Before submitting a change:

```bash
npm run check      # metadata, tests, strict build, link check
```

## Writing chapters

Chapters are plain MyST Markdown. See the
[MyST guide](https://mystmd.org/guide) for the full syntax.

### Section structure

Each chapter is one file. Numbered reading sections are `##` headings — rendered
*N.1*, *N.2*, … via `heading_1: true` in the chapter frontmatter — and are kept
roughly equal in length, so an assignment can be stated as "§§5.2–5.3". Topic
headings under a section are `###`; finer ones `####`. Learning Objectives and
Introduction stay unnumbered `###`. Summary, Conceptual Questions, and Problems
are `##` so they continue the section numbering.

**Quote any title containing a colon.** `title: Percussion: Membranes` is not a
YAML scalar, and MyST fails the frontmatter *silently* — the page still builds,
but its `label:` never registers and every cross-reference to the chapter
dangles. `npm run check:project` catches this.

### Admonitions, margin notes, dropdowns, and tabs

Use these sparingly — a handful per chapter, not per section — and only where
there is a genuine fit:

- `` ```{note} `` — historical or contextual asides.
- `` ```{tip} `` — problem-solving strategy. `` ```{tip} Self-check `` for a
  question the reader should be able to answer before moving on.
- `` ```{warning} `` — a misconception or pitfall specific to that topic.
- `` ```{seealso} `` — a pointer to related material, via `[](#label)`.
- `` ```{margin} `` — a short aside that would be a distracting parenthetical.
- `` ```{dropdown} Title `` — **the calculus goes here.** Any derivation that
  needs calculus is optional by construction, is labeled as such, and is never
  relied on later.
- `` ```{tab-set} `` — genuinely alternative treatments, not decoration.

### Exercises

```markdown
:::{exercise}
:label: ex-fourier-and-timbre-1

...
:::

:::{solution} ex-fourier-and-timbre-1
:label: sol-fourier-and-timbre-1
:class: dropdown

...
:::
```

Labels are `ex-<chapter-label-without-ch->-N` and `sol-…-N`. The student edition
drops every solution; both editions come from this one source.

## Audio examples

````markdown
```{audio} ch05-sawtooth
:label: fig:ch05-sawtooth
:transcript: A buzzy, nasal tone at 220 Hz, brighter than a sine at the same pitch.

Every harmonic of 220 Hz is present, with amplitude falling as 1/n.
```
````

The website shows an inline player above the waveform and spectrum; the caption
also links directly to the clip. PDF, DOCX, Markdown, and browser print keep the
figure, transcript, and link but omit the controls. **Always write a
`:transcript:`**: it is the only thing a reader has who is holding the PDF or
cannot hear the clip.

Clips are synthesized by [`scripts/audio/`](scripts/audio/), not recorded, so a
comparison can hold everything fixed but the one variable it is about.

## Interactive simulations

````markdown
```{openlyceum} StandingWaves
:label: fig:ch03-standing-waves-sim

Sweep the frequency; the string ignores you until you hit a harmonic.
```
````

`{openlyceum}`, `{phet}`, `{phet-legacy}`, and `{simulation}` are supplied by
[`plugins/simulation.mjs`](plugins/simulation.mjs). On the website this is a live
simulation; in print it becomes a screenshot with its caption and a link.

**Verify a new simulation slug before citing it.** A slug that does not exist
produces no error — the provider screenshot 404s and a generic placeholder card
appears instead.

## Staff notation

Notation is generated at build time by VexFlow from definitions in
[`notation/definitions/`](notation/definitions/), then **converted from font text
to plain paths**. That second step is not optional: Inkscape, which the print
pipeline uses to turn SVG into PDF, does not resolve the embedded WOFF2 music
font, so unconverted noteheads become dingbats in the PDF and the Word edition —
silently, and invisibly on the website.

```bash
npm run notation:render
npm run notation:check
```

## Figures

Generators live in [`scripts/figures/`](scripts/figures/); their SVG outputs live
in `images/` and are committed, because the Pages build has no Python. After
changing a generator, run it and commit both.

```bash
python3 -m pip install -r requirements-figures.txt
npm run check:figures
```

## Print and Word editions

```bash
npm run build:exports     # everything
npm run build:pdf         # the two book PDFs
npm run build:chapters    # per-chapter offprints
```

Requires Node 22, a TeX Live with XeLaTeX and latexmk, Inkscape (MyST converts
SVG to PDF with it and nothing else), pandoc, and poppler-utils.

Two environment variables steer `plugins/export.mjs`; neither is set for the
website build, where the plugin is inert:

| Variable | Values | Effect |
|---|---|---|
| `MYST_PRINT` | `full`, `student` | Which edition; `student` drops all solutions |
| `MYST_SITE_URL` | a base URL | Only for chapter offprints, whose cross-chapter references must leave the file |

`scripts/build-exports.sh` sets both correctly; prefer it to calling
`myst build` by hand.
